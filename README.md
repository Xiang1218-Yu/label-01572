# 游戏助手 - 阵容推荐页

深色电竞风格的阵容推荐中心，基于 React + TypeScript + Vite 构建，提供多维度筛选、搜索和阵容卡片展示功能。

> 本项目为纯前端演示项目，所有数据均为本地模拟数据（Mock Data），不依赖后端接口。数据定义在 `src/data/mockData.ts` 中，包含 8 条阵容、20 个英雄、10 件装备和 8 种羁绊。

## 题目内容
# 游戏助手-阵容推荐页需求文档 ## 一、概述 本页面是游戏助手工具的核心功能，定位为“阵容推荐中心”。其主要目标是为游戏玩家提供一个信息高度聚合的列表，方便玩家快速浏览、筛选和发现当前版本强势或有趣的阵容搭配，以提升游戏体验和决策效率。 ## 二、主题色调 - **主色调**：深邃的紫灰色 - **辅助色**：高亮的科技绿、醒目的金色 - **背景色**：深紫灰色主背景，搭配稍亮的同色系卡片背景 - **文字色**：白色主文案，浅灰色辅助文案 ## 三、页面风格 - **设计风格**：采用现代化的深色扁平设计，营造专业、酷炫的电竞氛围。 - **信息密度**：高密度信息陈列，便于资深玩家快速获取和比较信息。 - **UI细节**：广泛使用圆角、圆形元素，视觉统一；列表项之间有清晰的分割线，保证阅读的舒适性。 ## 四、整体布局 页面采用经典的三栏式布局，结构清晰，主次分明。 - **左侧区域 (固定)**：为**主导航栏**，纵向排列了通往产品所有核心功能的入口（如阵容、数据、英雄等），确保用户可以随时在不同模块间切换。底部集成了App下载的二维码，用于渠道引流。 - **右侧区域 (可滚动)**：为主内容区，自上而下分为三个部分：   1.  **顶部全局栏**：包含产品Logo、游戏版本切换菜单和用户中心入口，提供全局性的操作。   2.  **内容筛选区**：紧随其后的是一个强大的筛选模块，包括一个内容横幅、多个筛选标签页（如“国服最卷”、“最新”）、阵容强度评级按钮（SS/S/A等）以及一个关键词搜索框。此区域的功能是让用户能够精确地过滤下方列表。   3.  **阵容列表区**：占据页面主要空间的垂直滚动列表，用于展示所有阵容条目。 - **底部区域**：在页面内容滚动到底时，会显示标准的页脚，包含版权和相关服务链接。 ## 五、核心模块 ### 1. 阵容筛选与搜索模块 - **功能描述**：此模块是用户与阵容数据交互的起点，提供多维度筛选能力，帮助用户从海量阵容中快速找到目标。 - **包含组件**：分类标签页、评级按钮组、英雄搜索框。 - **布局位置**：主内容区顶部。 - **交互方式**：点击标签或按钮后，下方列表会立即刷新以展示过滤后的结果；在搜索框输入关键词，列表会相应地进行筛选。 ### 2. 阵容列表模块 - **功能描述**：以垂直列表的形式，集中展示所有经过筛选的阵容。这是页面的信息主体。 - **包含组件**：由多个“阵容列表项”组成。 - **布局位置**：主内容区，筛选模块下方。 - **交互方式**：支持垂直滚动浏览。当内容过多时，可考虑采用无限滚动或分页加载。 ### 3. 阵容列表项（卡片） - **功能描述**：作为列表中的基本单元，它以卡片形式高度概括了一个阵容的核心信息，是信息展示和导航跳转的关键。 - **包含组件**：     - **基础信息**：阵容标题、作者（头像+昵称）。     - **核心数据**：阵容评级（如SS）、难度标签（如新手推荐）、羁绊图标、核心英雄与装备、完整阵容英雄头像。     - **交互元素**：指向详情页的箭头图标。 - **布局位置**：在阵容列表模块中循环展示。 - **交互方式**：整张卡片可点击，点击后跳转至该阵容的详情页。鼠标悬停在卡片内的英雄、装备、羁绊等小图标上时，应出现悬浮提示框（Tooltip）显示其名称和简介。 ## 六、内容数据 - **主要数据类型**：核心数据类型为“游戏阵容”。 - **关键字段**：每个阵容需包含`标题`, `作者`, `评级`, `难度`, `羁绊列表`, `核心英雄与装备`, `完整英雄列表`等字段。 - **组织方式**：数据以列表形式组织，并支持基于评级、分类等字段进行筛选和排序。 ## 七、交互特征 - **点击跳转**：点击阵容卡片可跳转到对应的详情页。 - **悬浮提示**：鼠标悬停在游戏元素图标（英雄、装备、羁绊）上时，显示名称和说明的Tooltip。 - **实时筛选**：点击筛选条件后，阵容列表内容即时更新，提供流畅的筛选体验。 ## 八、非功能性需求 - **性能**：页面加载，特别是阵容列表的加载和筛选刷新速度要快，避免用户等待。 - **可访问性**：确保图标和文字有足够的对比度，关键交互元素（如按钮、链接）有清晰的视觉反馈。 - **响应式**：虽然截图为桌面端，但需考虑在不同屏幕尺寸下的适配方案，如在移动端将侧边栏收起为汉堡菜单。 其他要求：仅允许添加依赖项，禁止修改package.json中的scripts等非依赖字段。内容输出文件放在 ./src/pages/index.tsx。

## How to Run

```bash
# 使用 Docker Compose 一键启动
docker-compose up --build -d

# 访问用户端
# http://localhost:8081
```

手动启动（开发模式）：

```bash
cd frontend-user
npm install
npm run dev
# 访问 http://localhost:8081
```

运行测试：

```bash
cd frontend-user
npm install
npx vitest run
```

## 扫码测试（App 下载二维码）

侧边栏底部有一个"下载App"二维码，扫码后会跳转到 App 下载提示页面。测试步骤：

1. 确保手机和电脑连接同一个 WiFi 网络
2. 启动开发服务器：
   ```bash
   cd frontend-user
   npm run dev
   ```
3. 终端会显示局域网地址，类似：
   ```
   ➜  Network: http://192.168.x.x:8081/
   ```
4. 用手机扫描页面左下角的二维码
5. 手机浏览器会打开 `/download` 页面，显示"App 正在开发中，敬请期待"的提示

## 功能说明

| 功能 | 说明 |
|------|------|
| 阵容推荐列表 | 首页展示阵容卡片，支持按分类、评级、关键词多维度筛选 |
| 赛季版本切换 | 顶部下拉框切换 S14/S13.5/S13/S12.5，列表实时过滤 |
| 阵容详情页 | 点击卡片进入详情，展示羁绊、核心英雄装备、完整阵容 |
| 英雄图鉴 | 展示所有英雄卡片，按费用排序 |
| 装备图鉴 | 展示所有装备卡片及描述 |
| 羁绊一览 | 展示所有羁绊及激活人数 |
| 数据中心 | 阵容评级分布、赛季分布、英雄登场率/装备使用率/羁绊热度排行 |
| 用户中心 | 右上角面板，支持昵称编辑、收藏管理、浏览历史、数据重置（localStorage 持久化） |
| 收藏/历史 | 详情页可收藏阵容，自动记录浏览历史 |
| 响应式布局 | 移动端侧边栏收起为汉堡菜单，卡片/筛选区自适应 |
| Tooltip | 鼠标悬停英雄/装备图标显示名称和描述 |

## 数据说明

本项目使用本地模拟数据（Mock Data），所有数据定义在 `src/data/mockData.ts` 中：

| 数据类型 | 数量 | 说明 |
|----------|------|------|
| 阵容 (Lineup) | 20 条 | 分布在 S14(7)/S13.5(5)/S13(5)/S12.5(3) 四个赛季 |
| 英雄 (Hero) | 20 个 | 费用 1~5，含头像图片 |
| 装备 (Equipment) | 10 件 | 含图标图片 |
| 羁绊 (Synergy) | 8 种 | 含激活人数 |

数据不依赖任何后端 API，页面所有交互均在前端完成。如需对接真实接口，替换 `mockData.ts` 中的数据源即可。
